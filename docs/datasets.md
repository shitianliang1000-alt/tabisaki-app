# 学習データセット（旅の知恵・ReAct・未知の要望）

自前モデルに学ばせるのは、事実そのものより「旅の知恵」「道具を使う考えの流れ」「知らない要望への応じ方」です
（事実は収録と道具が答えます）。その3つと、収録から自動で作る指示をまとめたデータセットです（Issue #433）。

```sh
node tools/build_datasets.mjs           # training/datasets/ に4つの JSONL を作る（40秒ほど。何度走らせても同じ中身）
node tools/build_datasets.mjs --check   # 形と件数の点検（CI でも回ります）
node tools/export_training_data.mjs     # 学習データの書き出しに、これらを足して .tabisaki/training/ へ（--no-datasets で外す）
```

学習の一巡（`bash training/pipeline.sh`、[training.md](training.md)）は、最初の書き出しでこれらを読みます。

## 4つのファイル

| ファイル | 件数（学習／確かめ） | 中身 | 作りかた |
| --- | ---: | --- | --- |
| `tabisaki_wisdom.jsonl` | 72（65／7） | 旅の知恵: 混む時期の避け方、雨の日・山の天気・火山・台風、温泉や寺社のマナー、高齢の親や子ども連れのペース、地方のバス・終電・現金、旅館の夕食の時刻… | 手で書いた `seeds/wisdom.jsonl`（65項目、言い換えつき） |
| `tabisaki_react.jsonl` | 331（290／41） | 道具を使う考えの流れ。一手ごとに `{"thought","tool","args"}` を返し、道具の結果を読んで次の一手、最後に答え | 行動は手本として決め、**結果は本物の道具**（`packages/core/src/tools.js`）で取る |
| `tabisaki_meta.jsonl` | 226（206／20） | 収録に無い・決めきれない・無理な要望への応じ方（**いちばん大事**） | 手で書いた `seeds/meta.jsonl`（49場面）と、収録から作る型 |
| `tabisaki_instructions.jsonl` | 500（456／44） | 上の3つと、収録から作る指示から選んだ 500件 | 種類ごとに偏らないように選ぶ |

1行の形は、学習データの書き出しと同じ `{"messages":[…], "meta":{dataset, task, id, split, …}}` です。
`meta.split` が `"train"` か `"eval"` で、学習用・確かめ用を分けます。

### ReAct の場面（8種類）

| 場面 | 件数 | 道具の流れ |
| --- | ---: | --- |
| エリア×テーマ（「熊野市で神社をめぐりたい」） | 198 | `search_spots`（県で絞る）→ エリアの中の場所だけ選んで `calculate_route` → 答え。エリアの中に無ければ `ask_user` |
| 天気を調べる道具が無い（「明日、雨なら屋内に」） | 45 | 一覧に `search_weather` が無いので、屋内の場所を `search_spots` → 「天気は確かめられなかった」と書いて答える |
| 2か所のあいだの時間 | 24 | `search_transit`（乗り換え検索を切ってあるので距離からの目安）→ 「目安」と書いて答える |
| 収録に無い名前（ネットあり） | 23 | `search_spots` で0件 → `web_search` でも0件 → 作らずに `ask_user` |
| 収録に無い名前（ネットなし） | 20 | `search_spots` で0件 → 一覧に `web_search` が無いので `ask_user` |
| 名のある旅（最長片道切符・青春18きっぷ・船旅…） | 12 | `search_special_journey` → 旅の形を伝え、出発地と日数を聞く |
| 旧街道・国道 | 5 | `search_historical_route` → 沿う町を伝える（収録に無ければ、あるものを伝える） |
| 海外 | 4 | 範囲の外と判断し、似た雰囲気の国内の場所を `search_spots` → 断って代わりを出す |

最初の頼みは、推論のときと同じ形（`packages/core/src/guided.js` の `toolCallBody`、道具の一覧と JSON の形の指示）にしてあります。
いちばん長い行で 1,474 トークン（学習の長さの上限 2,048 に収まります）。

### 未知の要望（手で書いた49場面の種類）

足りない条件（どこ・いつ・誰と）、気分だけの頼み（癒やされたい・非日常）、無理な条件（日帰りで北海道と沖縄・0円で3泊）、
収録に無い名前、あいまいな地名（府中）、範囲の外（海外・ビザ・予約・薬）、価値の判断（いちばんいい温泉）、
いまの情報（いまの混み具合・今年の開花）、危ない・決まりに反する頼み（立入禁止の廃墟・ドローン・夜の山・冬の富士山・道の駅の車中泊）、
予算、家族で希望が分かれる、言い直し（日付・気分が変わる。2往復の会話）、配慮が要る（車椅子・食事の制限・犬）、
作り話の頼み（口コミを作って）、つらい気持ちで遠くへ行きたい、など。

収録から作る型: 海外12か所（どんな雰囲気が目当てかと、国内の行き先の種類を返す）、ありそうで無い名前（エリア名＋「ほしぞら岬」など。
収録に無いことを確かめてから使う）、遠すぎる日帰り（エリアどうしの直線距離が 800km 以上）、営業時間・料金が収録に無いスポット。

### 収録から作る指示（535件から148件を 500件に）

エリアの紹介（`kb/regions.json` の紹介文）、スポットの見どころ（旅さきで書いた説明文だけ）、営業時間・料金（収録にある値だけ）、
エリアの中の種類ごとの一覧。

## 守ること

- **事実を作らない。** 答えに書く場所の名前・数字は、収録か道具の結果にあるものだけです（試験で、エリア×テーマの答えの名前が
  道具の結果にあることを確かめています）
- **出典。** 収録から作る行は、学習に使ってよい出典（CC0・旅さきの収録データ・CDLA-Permissive-2.0・Apache-2.0）のスポットだけです。
  ReAct の道具も、その範囲に絞った収録の上で動かします。OpenStreetMap 由来の `osmInfo`（ODbL）と、Wikipedia 由来の説明文
  （CC BY-SA）は使いません。手で書いた seeds は旅さきのプロジェクトのものです
- **確かめ用への漏れ。** 同じ元（同じ seed・同じスポット・同じエリア）から作った行は、同じ側に入ります。スポットの行は、
  学習データの書き出しの `spot_fact` と同じ分け方なので、確かめ用のスポットの営業時間や料金が学習に入ることはありません
- **外に問い合わせない。** 天気と乗り換えの道具は「使わない」設定で動かすので、同じ収録なら同じ中身になります

## 採点との関係

`tools/model_eval.mjs` が採点するのは、これまでの4つ（スポットの事実・収録に無い場所・エリアの一覧・旅程）です。
データセットの「収録に無い名前」の行（`meta_unknown_name`）も、「見つからない」と言えたか（`unknown.refused`）で採点に加えました。
知恵・ReAct・ほかの未知の要望の行は、決まった正解が無いので採点では飛ばします（GPU で一巡したあと、答えを人が読んで見ます）。

## 足すとき

- 知恵・未知の要望を足すなら、`training/datasets/seeds/` の JSONL に1行足して `node tools/build_datasets.mjs` を走らせます。
  `variants`（言い換え）は、答えがそのまま通じるものだけにしてください
- 新しい ReAct の場面は、`tools/build_datasets.mjs` の `reactRows` に、行動の手順（`steps`）と答えの作り方（`answer`）を足します
