# プラグイン

旅さきに、ほかの人が作った **旅程のひな形** と **行き先の除外** を足す仕組みです。いまは端末（CLI・`packages/core`）でだけ使えます。

この文書は Issue #375 で決めたこと（仕様・脅威モデル・最初に作る範囲）をまとめています。

## できること

* **ひな形（templates）**: 「湯治」と書いたら「人の少ない温泉で、のんびり…・2日・電車」で組む、のような決まった頼みかた
* **除外（constraints）**: 遊園地を外す、このスポットを外す、のような行き先の絞り込み

> [!IMPORTANT]
> 第1版のプラグインは **データ（JSON）だけ** です。プラグインのコードは一切動かしません。理由は[脅威モデル](#脅威モデル)にあります。

## 使いかた

```sh
mkdir -p ~/.config/tabisaki/plugins
cp -r examples/plugins/jp.tabisaki.sample ~/.config/tabisaki/plugins/

./tabisaki plugins                          # 一覧と状態
./tabisaki plugins trust jp.tabisaki.sample # 中身を見て、使ってよいと決める
./tabisaki plan "湯治したい"                 # ひな形「静かな温泉旅」で組む
```

* 置き場所は `~/.config/tabisaki/plugins`（`XDG_CONFIG_HOME` があればその下）。`TABISAKI_PLUGIN_DIR` で変えられます
* **置いただけでは使いません。** `trust` すると、その時の中身の sha256 を `plugins.lock.json` に控えます。控えと中身が同じものだけを読みます
* 中身が1文字でも変わると「中身が変わった」になり、もう一度 `trust` するまで止まります（更新も同じ手順です）
* 外すときは `./tabisaki plugins untrust <id>`、消すときはそのフォルダを消します
* 一度だけプラグイン無しで組むときは `TABISAKI_PLUGINS=0 ./tabisaki plan …`
* ひな形を使ったときは、stderr に「ひな形「…」を使いました（プラグイン …）」と出します

| 状態 | 意味 |
|---|---|
| 使う | 控えと中身が同じ |
| まだ控えていない | 置いたが `trust` していない |
| 中身が変わった | 控えたあとに書き換わった。もう一度 `trust` するまで使わない |
| 宣言にまちがい | 形が正しくない（理由も出します） |

## 書きかた

1つのプラグインは、1つのフォルダと1つのファイルです。フォルダの名前は `id` と同じにします。

```
jp.tabisaki.sample/
└── tabisaki-plugin.json
```

見本は [examples/plugins/jp.tabisaki.sample](../examples/plugins/jp.tabisaki.sample/tabisaki-plugin.json) です。

```json
{
  "schema": 1,
  "id": "jp.tabisaki.sample",
  "name": "見本: 静かな温泉旅",
  "version": "1.0.0",
  "author": "旅さき",
  "license": "CC0-1.0",
  "api": 1,
  "contributes": {
    "templates": [
      { "name": "静かな温泉旅", "keywords": ["静かな温泉", "湯治"],
        "wish": "人の少ない温泉で、のんびり湯につかって休みたい", "days": 2, "transport": "transit" }
    ],
    "constraints": [
      { "name": "にぎやかな場所を外す", "exclude_categories": ["遊園地", "商店街"] }
    ]
  }
}
```

## 仕様

### 宣言（tabisaki-plugin.json）

| 項目 | 必須 | 中身 |
|---|---|---|
| `schema` | ✓ | `1`（このファイルの形の版） |
| `id` | ✓ | 英小文字・数字・`-` と `.`。逆さのドメイン名がおすすめ（`jp.example.onsen`） |
| `name` | ✓ | 60字まで |
| `version` | ✓ | `1.2.3` の形 |
| `author` | ✓ | 作った人 |
| `license` | ✓ | SPDX の名前（`CC0-1.0` など） |
| `api` | ✓ | 読める旅さきの版。いまは `1` |
| `description` | | 300字まで |
| `homepage` | | `https://` で |
| `contributes.templates` | | ひな形（50個まで） |
| `contributes.constraints` | | 除外（20個まで） |

* ファイルは 64KB まで。**知らない項目があれば、まちがいにします**（`main`・`permissions`・`hooks` のような、コードや権限を求める項目は第1版にはありません）
* ひな形: `name`（40字）・`keywords`（30字までを1〜10個）・`wish`（500字）・`days`（1〜14）・`transport`（`any` / `transit` / `car` / `walk` / `local`）・`from`（出発地の駅名）
* 除外: `name`・`exclude_categories`（スポットのカテゴリ、例: `遊園地`）・`exclude_spot_ids`（スポットの id）

### 動きかた

1. 旅さきは、置き場所の中の **フォルダ** だけを見ます（リンクはたどりません）
2. 各フォルダの `tabisaki-plugin.json` だけを読み、形を確かめ、sha256 を `plugins.lock.json` の控えと比べます
3. 控えと同じものの **除外** を、知識ベースに一度だけ当てます（全部のプラグインの除外を足し合わせます）
4. 希望の文が、ひな形の `name` と同じか `keywords` のどれかを含めば、そのひな形を頼みに重ねます。プラグインは名前の順に見て、最初に合ったものを使います
5. 利用者がオプションで書いた値（`--days` など）は、ひな形より勝ちます

### 版と互換

* `api` は、プラグインの形を壊す変更をしたときに上げます。旅さきは自分の版と同じ `api` のプラグインだけを読み、ちがえば「宣言にまちがい」で理由を出します
* 項目を足すだけの変更では `api` を上げません。そのかわり、古い旅さきは新しい項目を知らないので、そのプラグインを読みません（黙って一部だけ使うことはしません）
* プラグインの `version` は作った人が上げます。上げても控えは自動では変わりません

### 出所と署名

* 第1版では、**どこから入手したかを旅さきは知りません。** 信じる根拠は「利用者が中身を見て `trust` した」ことだけです
* `trust` で控える sha256 が、そのときの中身の証明です。あとから書き換わったものは使いません
* 公開鍵による署名（作った人の証明）は、配る場所（一覧・ストア）を作るときに決めます（[これから](#これから)）

## 脅威モデル

### 守るもの

| 守るもの | 中身 |
|---|---|
| 端末のファイル・鍵 | `.env`・SSH の鍵・ほかのアプリのデータ |
| 利用者の希望の文と位置 | 何を探したか、どこにいるか（[SECURITY.md](../SECURITY.md)） |
| 旅程の正しさ | 閉まっている・危ない・存在しない場所へ案内しない |
| 旅さき本体 | 本体のファイル・設定・ほかのプラグイン |

### 相手と入り口

* **悪意のある作者**: 便利そうなプラグインに、ファイルを盗む・通信する処理を混ぜる
* **乗っ取られた配り元**: もとは安全だったプラグインが、更新で悪いものに変わる
* **うっかり**: 形のまちがい、巨大なファイル、同じ名前のぶつかり

### 脅威と対策

| 脅威 | 第1版の対策 | 試験 |
|---|---|---|
| プラグインのコードが端末で動く（ファイル・鍵を盗む、通信する） | **コードを動かさない。** 宣言は JSON だけで、`main`・`hooks` のような項目は断る | 宣言: 知らない項目・コードを指す項目… |
| 権限の求めすぎ | 権限という考えが無い（ファイル・通信・ほかへのアクセスは、どれも持てない） | 同上（`permissions` を断る） |
| 置いただけで勝手に効く | `trust` で控えたものだけ読む | 置いただけでは使わない… |
| 更新で中身がすり替わる | sha256 の控えとちがえば止める | 控えたあとに中身が変わったら… |
| リンクで置き場所の外のファイルを読ませる | リンクのフォルダは見ない。宣言がふつうのファイルでなければ断る | 置き場所の外を指すリンク… |
| 巨大なファイルで止める | 64KB まで、ひな形50・除外20・言葉の長さに上限 | 同上・宣言の試験 |
| 名前のなりすまし（別のフォルダに同じ id） | フォルダの名前と `id` が同じでなければ断る | 同上 |
| 依存パッケージ経由の攻撃 | 依存という考えが無い（JSON 1つだけ） | — |
| 希望の文・位置を外へ出す | プラグインは文を受け取らない（旅さきが言葉を照らすだけ）。通信の手段も無い | — |
| 旅程をゆがめる（危ない場所へ誘う） | できるのは **除くこと** と **頼みを決まった形にすること** だけ。スポットを足す・時刻や説明を書き換えることはできない | 除外: … |
| ひな形が利用者の指定を上書きする | 利用者が書いた値が勝つ。使ったひな形の名前を必ず出す | ひな形: … |
| 除外しすぎて旅程が組めない | 組めなければ、ふだんと同じく「組めなかった」で終わる（`TABISAKI_PLUGINS=0` で外せる） | — |
| 消したつもりで残る | `untrust` で控えから外れ、フォルダを消せば何も残らない（ほかの場所に書き込まない） | trust・untrust の試験 |

### 残る危険

* **ひな形の文そのもの**: 利用者が `trust` で中身を見ることを前提にしています。`./tabisaki plugins` で名前・作者・ライセンスを出します
* **控え（plugins.lock.json）を書き換えられる**: 端末をすでに乗っ取られている場合で、プラグインの仕組みでは防げません
* **Web 版・API サーバー**: まだプラグインを読みません。読むようにするときは、この表を見直します

## 第1版でやらないこと

| やらないこと | なぜ |
|---|---|
| プラグインのコード（JS・WASM）を動かす | Node.js の `vm` は隔離になりません。安全に動かすには別の仕組み（下）が要ります |
| スポットを足す | 収録データは出典とライセンスを確かめています（[data-licenses.md](./data-licenses.md)）。第三者が足したものを同じ扱いにできません |
| 通信・ファイルの読み書き | 第1版のできることに要りません |
| Web 版・API サーバーで読む | 配りかたと選びかた（画面）が決まっていません |
| 配る場所・自動の更新・署名 | 使う人が増えてから決めます |

## これから

使われかたを見て、次の順に考えます。どれも、この脅威モデルを先に直してから入れます。

1. **Web 版で読む**: 公式に確かめた一覧から選ぶ形にする（利用者が任意の URL を読み込む形にはしない）
2. **署名**: 配る場所を作るときに、作者の公開鍵（minisign や Sigstore）で中身の sha256 に署名し、`trust` で作者も控える
3. **コードを動かす**: 要るとわかったときに、別の process（Node.js の権限の仕組み `--permission` で、ファイル・通信・子 process を全部止める）か WASM の中で、決まった入力（旅程の JSON）と出力だけをやりとりする形を考えます
