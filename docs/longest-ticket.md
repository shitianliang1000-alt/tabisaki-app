# 最長片道切符のソルバー

「最長片道切符で旅したい」と頼まれたときに、JR の線路を同じ駅を2度通らずに
いちばん長くたどる経路を出す仕組みです（Issue #431）。

- 路線網: `packages/core/rail/jr-graph.json`（駅 4,249・辺 4,379・営業キロの合計 17,427.8km・176線）
- ソルバー: `solver/longest-ticket/`（Rust）。WebAssembly にしたものを `packages/core/rail/longest_ticket.wasm` に置いています
- Node.js からの入口: `packages/core/longest-ticket.mjs`
- つなぎ: `core.special()`・`core.research()` は、何も渡さなくてもこのソルバーを使います（Node.js のときだけ。サイトとアプリには入れていません）

## 何が返るか

```js
import { createLongestTicketSolver } from "tabisaki-core/longest-ticket.mjs";
const solve = await createLongestTicketSolver({ limitMs: 5000 });
const r = await solve("oneway", { from: "東京" });   // from を省けば全国
r.km;        // 営業キロ（往復 "round" なら2倍）
r.stations;  // 通る駅の順
r.legs;      // 乗る線ごとの区間 {line, from, to, km}
r.proven;    // これより長い経路が無いと確かめられたか
r.note;      // 利用者に添える一言
```

**全国の網では `proven` は `false` です。** 制限時間内に見つかったいちばん長い候補を返し、
`note` にもそう書きます。理由は下の「確かめきれない理由」にあります。
小さな網（テストの網や、地方だけに絞った網）なら、最長と確かめて早く返ります。

出発駅は、頼みに「○○から」「○○発」と書かれたときだけ決めます（`ticketStart()`、
`packages/core/src/special.js`）。家の最寄り駅（`origin`）はソルバーに参考として渡すだけで、
出発駅にはしません。最長片道切符は端の駅から始めたほうがずっと長くなるからです。

- 1秒でも、10秒かけたときの 98% ほどの長さが出ます。2秒から先は、ほとんど伸びません
- 出発駅を決めない「全国」の候補が、稚内から出した候補より短いことがあります。どちらも候補で、
  組み替えの探索がどこで止まるかによります（出発駅を決めないほうが、探す範囲が広いぶん迷います）
- 世の中で知られている最長片道切符（運賃の規則どおりに数えたもの）と、ここで出る候補は
  一致しないことがあります。路線網の作りかた（下）が運賃の規則と少し違うことと、
  最長と確かめきれていないことの両方が理由です
- CI では制限時間 2秒で 24通りを測り、時間内に返ることと、8,000km を超えることを確かめます

## どう解くか

1. **網を縮める。** 分かれ道の無い駅は辺の中にたたみ、分かれ道（3本以上の線が集まる駅）と
   行き止まりだけを残します。4,249駅が 335の点・465の辺になります
2. **境目の動的計画法（frontier DP）。** 辺を1本ずつ「使う・使わない」と決めながら、
   まだ決めていない側との境目の駅だけを覚えて進みます。上限（まだ使える辺の長さ）で
   見込みの無い途中経過を捨てます（分枝限定法）
3. **組み替え（大近傍探索）。** 2. が時間内に終わらなければ、それまでに見つかった経路の
   一部を切り取り、そこだけ 2. で解き直したり、別の道でつなぎ直したり、端を伸ばしたりして、
   長くなれば採ります。時間いっぱい繰り返します
4. **確かめる。** 返す前に、同じ駅を2度通っていないこと・通り抜け禁止の駅を通り抜けて
   いないことを、ソルバーとは別のコードで確かめます

経路の形は3つです。ふつうの1本道、最後に通った駅へ戻って終わる「6の字」、出発駅へ戻る輪。
往復（"round"）は1本道だけを使い、同じ道を引き返します。

### 確かめきれない理由

2. の速さは「境目の幅」（同時に覚えておく駅の数）で決まります。JR の網では幅が 14 になり、
途中経過が数百万を超えて、手元の計算機では最後まで行けません。そこで 2. には残り時間の
3割だけを使い、途中経過は良いものから一定の数だけ残して（ビーム）、残りの時間を 3. に回します。
小さな網での試験では、3. だけで最長の 90〜100% に届きます（`solver/longest-ticket/tests/random.rs`）。

## 路線網の作りかた

素データは日本語版ウィキペディアの各駅の記事の情報欄（`{{駅情報}}`）です。
集めるのは `tools/fetch_rail_stations.py`、路線網に直すのは `tools/build_rail_graph.py` です。
決めごとはスクリプトの先頭と `PATCHES` に、理由と一緒に書いてあります。主なもの:

- 両側の駅の記事で「となりの駅と営業キロ」が合ったものを辺にします。食い違えばキロ程の差で決めます
- 廃止された駅・まだ開業していない駅（「2028年予定」など）は入れません
- 快速が通過する駅を飛ばした辺など、ほかの辺をつないだ道のりと営業キロが同じ辺は落とします
- 新幹線は、並行する在来線と同じ線として扱います（旅客営業規則 第16条の2）。
  新幹線にしかない駅をはさむ次の 16区間だけは別の線として残し、新幹線にしかない駅
  （新横浜・古川・新花巻・燕三条・新鳥栖）は乗り換えにだけ使える「通り抜け禁止」にしています。
  品川―小田原、三島―静岡、名古屋―米原、新大阪―西明石、三原―福山、広島―三原、徳山―広島、
  仙台―福島、一ノ関―仙台、北上―一ノ関、盛岡―北上、熊谷―高崎、高崎―越後湯沢、新潟―長岡、
  久留米―博多、熊本―筑後船小屋
- 山陽新幹線の新下関―小倉―博多は、在来線（JR九州）と別の線として残します
- ミニ新幹線（秋田・山形）は在来線として数えます
- 海峡線（中小国―木古内）は旅客列車が走っていないので入れません。青函トンネルは北海道新幹線で通ります
- JR のほかの線とつながらない線（越美北線・七尾線・大湊線）は外します（`isolated` に記録）
- 予土線の窪川―若井（4.4km）は土佐くろしお鉄道の線ですが、予土線の列車が乗り入れるので残しています
- BRT と船は入れていません

確かめた営業キロ: 宗谷本線 259.4km・土讃線 198.7km・指宿枕崎線 87.8km（線の全長）、
東京―千葉 39.2km・東京―横浜 28.8km・札幌―旭川 136.8km・名古屋―米原 79.9km（新幹線）など。

### 作り直すとき

```sh
python3 tools/fetch_rail_stations.py            # 配布ファイルを流しながら読む（約25分。data/rail-raw/ へ）
python3 tools/build_rail_graph.py               # 数と、合わなかったものを見る
python3 tools/build_rail_graph.py --write       # jr-graph.json に書く
node --test tests/longest-ticket.test.js
```

ソルバーを変えたら `sh tools/build_longest_ticket.sh`（Rust のテスト → WebAssembly → コピー）を
走らせ、`.wasm` も一緒にコミットします。使う側は Rust が無くても動きます。
