# GTFS-JP の取得から OpenTripPlanner への反映まで

公開されている GTFS-JP（時刻表）を集めて、検査して、手元の OpenTripPlanner（OTP）に読ませるまでを、
1本のコマンドでやり直せるようにした仕組みです（Issue #430）。OTP そのものの動かしかたと、
旅程づくりへのつなぎかたは [otp.md](otp.md) にあります。

```sh
bash tools/otp_pipeline.sh            # 熊本
bash tools/otp_pipeline.sh toyama     # 富山
```

| 段 | すること | 道具 |
| --- | --- | --- |
| 1 | 時刻表の一覧（[GTFS データリポジトリ](https://gtfs-data.jp/)）を取り、地域の時刻表を決める | `tools/gtfs_feeds.py`・`tools/otp_fetch.py` |
| 2 | 一覧の公開日が変わったものだけ落とし、検査する。通らないもの・期限切れは外す | `tools/gtfs_feeds.py` |
| 3 | 読ませる時刻表が前の組み立てと同じなら、組み立てを飛ばす | `feeds.json` と `graph-feeds.json` を比べる |
| 4 | 経路網を組み立てる | `docker compose --profile otp run --rm otp-build` |
| 5 | OTP を起こし直し、答えるまで待つ | `docker compose --profile otp up -d otp` |
| 6 | 収録のスポットどうしで試しに引き、1組も返らなければ失敗にする | `tools/otp_bench.mjs --check` |

週に1回ほど cron で回せば、時刻表の改正が自動で入ります（変わっていなければ 1〜3 だけで終わります）。

```cron
0 5 * * 1  cd ~/tabisaki-app && bash tools/otp_pipeline.sh kumamoto >> data/otp/pipeline.log 2>&1
```

## 地域のファイル

`otp/regions/<地域>.json` に、地図の範囲と、時刻表の決めかたを書きます。

```json
{
  "name": "富山（富山市・高岡市と、そのまわり）",
  "osm": { "extract": "https://download.openstreetmap.fr/extracts/asia/japan/chubu.osm.pbf",
           "bbox": [136.85, 36.50, 137.45, 36.87] },
  "select": { "prefectures": [16], "min_stops": 3, "exclude": [] }
}
```

- **`select`（自動）**: 県の時刻表を一覧から全部見て、範囲（`bbox`）の中に停留所が `min_stops` 以上あるものを使います。
  一覧に新しい事業者が載れば、次に回したときに自動で入ります。外したいものは `exclude` に `事業者/時刻表` で書きます。
  運行をやめた時刻表（一覧の `feed_is_discontinued`）は見ません
- **`feeds`（決め打ち）**: `{"org": …, "feed": …, "name": …}` を並べます。一覧に無い時刻表（ODPT など）は
  `url`・`license`・`publisher` も書きます。鍵の要る URL は `{ODPT_KEY}` のように書くと、環境変数から入れます
  （鍵はファイルにもログにも残しません。環境変数が無ければ、その時刻表だけ「落とせない」として外します）。
  一覧に無い時刻表は公開日が分からないので、新しくしたいときは `version` を書き換えます

熊本・富山とも `select` です。熊本は県の時刻表 6本がすべて範囲に入るので、前の決め打ちと同じ 6本になります。
富山は県の 25本（運行をやめたものを除く）から、範囲の外の2本と期限切れの1本を外した 23本です。

## 回した結果

| | 熊本 | 富山 |
| --- | ---: | ---: |
| 読ませた時刻表 | 6 | 23 |
| 外した時刻表 | 0 | 3（範囲の外 2・期限切れ 1） |
| 直した時刻表 | 4（古い translations.txt） | 2（運賃のルール 1,060行・古い translations.txt） |
| 組み立て | 41秒 | 32秒 |
| 範囲のスポットのうち、800m 以内に便のある停留所 | 70.4% | 81.8% |
| 収録のスポットどうし 100組で経路が返った | 73組 | 59組 |
| 応答時間 中央値 / 90% | 156ms / 430ms | 52ms / 144ms |
| 2回目（時刻表が変わっていない） | 組み立てを飛ばす | 組み立てを飛ばす |

富山は停留所のそばにあるスポットが多いのに、経路が返る組が少なめです。富山地方鉄道の鉄道線・あいの風とやま鉄道・
JR の時刻表が GTFS で公開されていないため、鉄道でつながる組（富山〜立山、富山〜魚津など）が、
路線バスだけでは時間内に届かないことが多いからです。富山地方鉄道市内電車は、時刻表の中で路線の種類が
バス（`route_type` 3）になっているので、表でもバスに数えています。

## 検査

落とした zip ごとに、次を確かめます（`python3 tools/gtfs_feeds.py check FILE.zip` で1つだけ見られます）。

**読ませない（外して、理由を `COVERAGE.md` に書く）**

- zip として読めない（落とした中身が HTML のエラーページだった、など）
- `agency.txt`・`stops.txt`・`routes.txt`・`trips.txt`・`stop_times.txt` が無い、または要る列が無い
- `calendar.txt` も `calendar_dates.txt` も無い
- UTF-8 で読めない、便が1つも無い、停留所につながる時刻が1つも無い
- 有効期間が切れている

**読ませるが、数を記録する**

- 路線・運行日・便・停留所がつながらない参照
- 日本の範囲の外にある停留所（緯度と経度の取り違えが多い）、位置が読めない停留所
- 読めない時刻（`9:7` のような書きかた）、停まるところが2つ未満の便

**OTP に読ませる前に直す（`otp_fetch.py`）**

OTP（時刻表の読み込みに使っている onebusaway）は、参照先の無い行が1行でもあると、組み立てを途中で止めます。
そこで、地域のフォルダに写した時刻表から、その行だけを外してから読ませます（外した数はログに出ます）。

- 運賃のルールが、無い運賃を指している（富山地方鉄道バスで 1,060行。これで富山の組み立てが止まっていました）
- 便が無い路線を、時刻が無い便・停留所を、乗り継ぎ・運行間隔が無い便・停留所を指している
- 停留所の親（`parent_station`）が無い（親の欄だけ空にします）
- GTFS-JP 第2版までの `translations.txt`（形が違うので、ファイルごと外します）

有効期間は `calendar.txt` と `calendar_dates.txt` から出し、`有効`・`まもなく切れる`（30日未満）・`これから`・`期限切れ` に分けます。
一覧だけを見て期限を調べることもできます（落としません）。

```sh
python3 tools/gtfs_feeds.py expiry --pref 43,16      # 切れた・30日以内に切れる時刻表
```

## カバー範囲

時刻表があっても、スポットのそばに停留所が無ければ使えません。そこで、検査のときに停留所ごとの
**1日の発車数**（有効期間の中で、今日から先の最初の水曜）を数え、収録のスポットと突き合わせています。

- 地域ごと: `data/otp/<地域>/COVERAGE.md`（時刻表ごとの中身・外したものと理由・歩いて行ける停留所の無いスポットの一覧）
- 全国: `python3 tools/gtfs_feeds.py fetch` で一覧の全部を落としてから、`python3 tools/gtfs_feeds.py coverage --md`。
  結果は [gtfs-coverage.md](gtfs-coverage.md) に写してあります

「歩いて行ける」は直線 800m（歩いて10分ほど）、「便が多い」は1日10本以上（だいたい1時間に1本）としています。
発車のない停留所（その日は走らない路線だけの停留所）は数えません。

## ODPT（公共交通オープンデータセンター）

ODPT の時刻表の多くは、利用者登録をして受け取る鍵（`acl:consumerKey`）が要ります。鍵は中継やサイトには
置かず、この道具を動かす機械の環境変数 `ODPT_KEY` にだけ入れます。GTFS データリポジトリに載っている
時刻表は、鍵なしで落とせるので、まずはそちらを使います。

## ライセンス

時刻表は事業者ごとのライセンスです（一覧では CC BY 4.0 が 474本、CC0 1.0 が 82本、CC BY 2.1 JP が 52本）。
`otp_fetch.py` は、読ませた時刻表の事業者名・ライセンス・ライセンスの URL を `data/otp/<地域>/SOURCES.md` に
書き出します。経路の答えを公開の場で出すときは、この表示を添えてください。落とした zip と検査の結果
（`data/gtfs/`）はリポジトリに入れていません。
