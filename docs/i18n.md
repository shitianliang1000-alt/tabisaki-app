# 多言語対応（i18n）

旅さきを日本語以外で使えるようにするための決まりと、翻訳を送ってもらう流れです。

原文は日本語です。訳が無いところは、黙って空にせず**日本語の原文**を出します。

## 対応している言語

| 言語 | 状態 | 範囲 |
|---|---|---|
| 日本語（`ja`） | 原文 | すべて |
| 英語（`en`） | 最初の訳 | 端末の旅程（`./tabisaki plan --lang=en`）と手元 API の Markdown（`"lang": "en"`） |

次の言語（中国語の簡体字・繁体字、韓国語など）は、英語で流れが固まってから、訳してくれる人が見つかった言語から足します。

言語は次の順で決まります。端末の `LANG` は見ません（英語の設定の端末で日本語を使っている人が多いので、勝手に変えません）。

1. `--lang=en`（API では本文の `"lang": "en"`）
2. 環境変数 `TABISAKI_LANG`（`en`・`en_US.UTF-8` なども読めます）
3. 日本語

## 訳す範囲

| 対象 | 置き場所 | 状態 |
|---|---|---|
| 旅程の見出し・表の頭・注意書き（CLI・API） | `locales/<言語>.json` | ✅ ある |
| 端末の画面（`./tabisaki tui`）・`help` の文 | `locales/<言語>.json` | 📝 これから |
| エンジンが作る文（「昼食」「〜へ移動」、注意の文） | `locales/<言語>.json` | 📝 これから（`js/` から文を抜き出す） |
| Web 版の画面（`index.html`・`js/ui.js` など） | `locales/<言語>.json` | 📝 これから（PHP 版もそろえる） |
| スポットの名前・説明 | `kb/i18n/<言語>/` | 🚧 しくみだけある（訳はまだ無い） |
| AI の答え | AI に言語を伝える | 📝 これから |

## 数・日付・時刻の出しかた

| もの | 決まり | 日本語 | 英語 |
|---|---|---|---|
| 時刻 | **いつも日本時間**、24時間 | `08:05` | `08:05` |
| 日付 | 言語の書きかた（`Intl.DateTimeFormat`） | `11/3(火)` | `Tue, Nov 3` |
| 時間帯 | 範囲の記号だけ変える | `08:00〜10:27` | `08:00–10:27` |
| 距離 | km のまま（マイルに直さない） | `3.3km` | `3.3 km` |
| お金 | 円のまま（両替はしない） | `21,700円` | `¥21,700` |

時刻を日本時間に固定するのは、旅先が日本で、時刻表も営業時間も日本時間だからです。海外の端末で見ても、時刻はずれません。

## 画面の文の翻訳ファイル

`locales/<言語>.json` に、平らな JSON で書きます。原文は `locales/ja.json` です。

```json
{
  "_meta": { "lang": "en", "name": "English", "source": false },
  "plan.day": "Day {n}",
  "plan.days.one": "Length: {n} day",
  "plan.days.other": "Length: {n} days"
}
```

* **鍵** は `場所.意味` の形にします（`plan.day`）。原文（`ja.json`）に無い鍵は足せません。
* **差し込み** は `{名前}` です。原文と同じ名前を、同じ数だけ使ってください（順番は変えてかまいません）。
* **数で形が変わる文** は、鍵の後ろに `.one`・`.other` などを付けます（`Intl.PluralRules` の区分）。日本語は `.other` だけです。
* **訳が無い鍵** は日本語の原文が出ます。原文にも無ければ、鍵そのもの（`plan.day`）が出ます。

読み出すのは [`packages/core/i18n.mjs`](../packages/core/i18n.mjs) です。ファイルを読まない作りなので、Web 版からもそのまま使えます。

## スポットの名前・説明の訳

収録データ（`kb/`）の文は、原文をそのまま残し、訳を**別のファイルに重ねます**。収録ファイルは書き換えません。

```text
kb/spots-jp26-kyoto.json          原文（日本語）
kb/i18n/en/spots-jp26-kyoto.json  英語の訳（同じファイル名）
```

```json
{
  "lang": "en",
  "spots": {
    "kyoto-higashiyama-1": {
      "name": "Kiyomizu-dera",
      "description": "An old temple in Higashiyama whose stage looks out over the city.",
      "by": "human",
      "sourceHash": "1a2b3c4d"
    }
  }
}
```

* `by` は、人が訳したら `human`、機械翻訳なら `machine` です。`machine` の訳は、画面で「機械翻訳」と分かるようにします。
* `sourceHash` は訳の元にした原文の指紋です（`sourceHash()`、名前と説明から作ります）。原文が直ると指紋が変わり、その訳は使われず原文が出ます。点検で「見直してください」と出るので、訳を直して指紋を付け直します。
* 名前は、まず**公式の英語表記**を使います。無ければヘボン式のローマ字で、寺社は `-ji`・`-dera`・`-jinja` のように付けます（`Kiyomizu-dera`）。
* 地名の読み替え（`Sendai` → 仙台市）は [`js/romaji.js`](../js/romaji.js) にあり、これとは別です。

### 原文と出典

訳は原文から作ったものなので、**原文と同じ条件**に従います。たとえば Wikipedia の文を元にした説明の訳は CC BY-SA で、出典は原文の出典（`kb/index.json` の `sources`）のままです。訳した人は PR の履歴に残ります。条件は [data-licenses.md](data-licenses.md) を見てください。

## 翻訳の流れ

1. `locales/ja.json`（スポットなら `kb/` の収録ファイル）を見て、訳すところを決める
2. `locales/<言語>.json`（スポットなら `kb/i18n/<言語>/`）に訳を書く
3. 点検を通す

   ```sh
   node tools/i18n_check.mjs          # 誤りがあれば終了コード 1
   node --test tests/i18n.test.js
   ./tabisaki plan "京都で歴史を感じたい" --lang=en
   ```

4. PR を出す（ひな形の「何を変えたか」に、訳した言語と範囲を書く）
5. その言語が読める人が1人見て、良ければ持ち主がマージする

CI でも `tools/i18n_check.mjs` が走り、訳の進み具合が実行結果のまとめ欄に出ます。

| 点検の結果 | 例 | 扱い |
|---|---|---|
| 誤り | 原文に無い鍵、差し込みの名前が合わない、訳の元のスポットが無い | CI が止まる |
| 気になる点 | まだ訳していない鍵、原文が変わって古くなった訳 | 止めない（原文が出る） |

## 新しい言語を足す

1. `packages/core/i18n.mjs` の `LANGS` と `intlLocale` に言語を足す
2. `locales/<言語>.json` を作り、`_meta` を書く
3. この文書の「対応している言語」の表に1行足す
