# 旅の感想（任意）

行ってきた旅で「見込みと違ったところ」を、利用者が任意で残すしくみです。営業時間・移動時間・滞在時間の見積もりを、実際に回った人の手がかりで直すために使います。

> 書かなくても、何も変わりません。残すのはその端末の中だけで、送るのは利用者が自分で送ったときだけです。

## 目的

旅程は「この時間で回れるはず」という見込みで組んでいます。行ったら閉まっていた、乗り継ぎが間に合わなかった、1時間では足りなかった、といった外れは作る側からは見えません。感想は次の2つにだけ使います。

- 知識ベース（`kb/`）の営業時間・定休日・閉業の訂正
- 移動・滞在の見積もりと制約処理（`js/planner.js`・`js/hours.js` など）の見直し

## しくみ

- 旅程の画面の下に「この旅はどうでしたか？（任意）」が**畳んだ状態**で出ます。旅の始まり（1日目の最初の時刻）を過ぎた旅程にだけ出ます。前に作った旅は「最近のチャット」から開けます。
- 立ち寄り先ごとに「行けた / 行けなかった」と、決まった心当たりを選びます。旅全体の詰め具合も選べます。
- 「この端末に残す」でブラウザの `localStorage`（キー `tabisaki.feedback`）に入ります。
- 残っている感想は、画面で**まとめ**（Markdown の表）として読めます。開発者に知らせたいときは、利用者が「まとめをコピー」するか、「GitHub で開発者に知らせる」で Issue の画面を開き、中身を確かめてから自分で送ります。
- 実装は `js/feedback.js`（データ）と `js/ui.js` の `feedbackBox`（画面）。試験は `tests/feedback.test.js`。

## 集める項目

| 項目 | 値 |
|---|---|
| 立ち寄り先 | 知識ベースの id と名前（旅程に出ていたもの） |
| 行けたか | 行けた / 行けなかった |
| 心当たり | 営業時間が違った / 休みだった・入れなかった / 移動が間に合わなかった / 時間が足りなかった / 時間が余った / 混んでいて待った |
| 詰め具合 | ちょうどよかった / きつかった / ゆるかった |
| エリア名 | 旅程の見出しのエリア（例: 鎌倉） |
| 残した時刻 | 保存期間を数えるためだけに使います |
| 旅の印 | 立ち寄り先の id の並びから作った短い符号。同じ旅を開き直したときに上書きするためのもので、元には戻せません |

## 集めないもの

- 自由に書ける文（同行者の名前や泊まった場所のような、改善に要らない個人の情報が入りうるため）
- 出発地・帰着地、位置情報、旅行の日付、入力した希望の文
- 端末やブラウザの識別子、Cookie、IP アドレス

選べる値は `js/feedback.js` の `STATUS`・`ISSUES`・`PACE` に決め打ちしてあり、それ以外の値は保存の前に落とします。

## 同意

- 欄は畳んであり、開いて選び「この端末に残す」を押したときだけ残ります。既定では何も残しません。
- 開発者に届くのは、利用者が GitHub の画面で送ったときだけです。その画面には本文がそのまま出るので、送る前に読めます。GitHub の Issue は公開されます。
- 使われかたの件数（`js/metrics.js`、Analytics Engine を有効にするまで止まっています）とは別のしくみで、感想を件数に混ぜることも、自動で送ることもしません。

## 保存期間と削除

| | |
|---|---|
| 端末の中 | 最後に残してから **180日**。過ぎたものは次に読むときに消えます。覚えるのは **50件**まで（古いものから消えます） |
| 1つの旅を消す | 感想の欄の「この旅の感想を消す」 |
| すべて消す | まとめの下の「感想の記録をすべて消す」、またはブラウザのサイトデータの削除 |
| GitHub の Issue | 送った人が自分で編集・削除できます。開発者は、反映した Issue を閉じます |

## 集計して直すまで

1. 届いた Issue（題名が「[旅の感想]」、ラベル `feedback`）を読みます。まとめには立ち寄り先の id が入っています。
2. 同じスポットで「営業時間が違った」「休みだった」が重なっているときは、出典を確かめて[スポット情報の訂正](../.github/ISSUE_TEMPLATE/spot_report.md)の Issue にし、`tools/apply_kb_edits.mjs` で直します。
3. 「移動が間に合わなかった」「時間が足りなかった」「きつかった」が重なっているときは、見積もり（移動の余裕・滞在時間・詰め具合）の Issue にします。
4. 元の感想の Issue は、つないだ先の Issue を書いて閉じます。
