# 地域別の知識ベースと、似たスポットの検索

収録（`kb/`、全国54,101か所）から、行く地域のぶんだけを切り出し、端末の中で似たスポットを探せます。
通信はしません。外の部品も要りません。

```bash
./tabisaki kb extract --region=関東       # .tabisaki/kb/関東.json
./tabisaki kb index --region=関東         # .tabisaki/index/関東.json
./tabisaki similar "清水寺"
```

この文書は Issue #353 で決めたことをまとめています。

## 地域の指定

`--region=` には、次のどれでも書けます。カンマで区切って並べることもできます（`--region=京都府,奈良県`）。

| 書きかた | 例 |
|---|---|
| 8地方区分 | 北海道・東北・関東・中部・近畿（関西）・中国・四国・九州 |
| よく使う呼びかた | 北陸（富山・石川・福井）・甲信越・東海（岐阜・静岡・愛知・三重）・九州沖縄・沖縄 |
| 都道府県 | 京都府・京都・東京都・北海道 |
| 全部 | 全国 |

## 切り出しの中身

```json
{
  "version": 1,
  "region": "関東",
  "prefectures": ["茨城県", "…", "神奈川県"],
  "kbHash": "05414b3fdff4852b",
  "files": ["spots-jp08-ibaraki.json", "…"],
  "counts": { "regions": 168, "spots": 9545 },
  "sources": [{ "name": "国土数値情報 観光資源（国土交通省）", "url": "…" }, "…"],
  "spotsBySrc": { "kokudo": 1234, "wikidata": 2345, "…": 0 },
  "notice": "外から取り込んだデータは、それぞれの提供元の条件に従います…",
  "regions": [{ "id": "hakone", "name": "箱根", "…": "…" }],
  "spots": [{ "id": "…", "name": "…", "category": "寺院", "lat": 35.0, "lng": 139.0, "src": "wikidata", "…": "…" }]
}
```

* **同じ `kb/` からは、いつ走らせても同じ中身**になります。日時は入れず、かわりに元のファイルの指紋（`kbHash`、SHA-256 の頭16字）を入れます。`kb/` が変われば `kbHash` も変わります
* スポットに残す項目: 名前・分類・座標・エリア・説明・有名度・滞在の目安・営業時間・料金、それと**出典の項目**（`src`・`source`・`dataSource`・`license`・`osm`・`overture`・`wikipedia`・`url`）
* 置き場の `.tabisaki/` は `.gitignore` 済みです。`--out=<ファイル>` で別の場所にも書けます

## 似たスポットの検索

```bash
./tabisaki similar "金閣寺"                       # 全国から
./tabisaki similar "首里城" --region=沖縄 --limit=5
./tabisaki similar "紅葉の寺" --output=json         # 名前が収録に無ければ、文として探す
./tabisaki similar "東大寺" --index=.tabisaki/index/奈良県.json   # 作っておいた索引を使う
```

* 名前が収録にあれば、そのスポットを起点にします。**同じ名前がいくつもあるとき**（清水寺は全国に17件）は、手で確かめた収録（説明つき）→ 同じ名前の Wikipedia 記事がある → 有名度、の順で選びます。別の清水寺を起点にしたいときは `--region=` で絞ってください
* 起点から 0.5km 以内の同じ分類は、出典ちがいで2件入っている同じ場所とみなして外します
* 出すのは、名前・分類・エリア・都道府県・起点からの距離（km）・似ている度合い（0〜1）です
* 索引が無いときは、その場で作ります（全国で1〜2秒）

## 検索のしかたを選んだ理由

収録のスポットの多くは「名前・分類・座標」だけで、説明があるのは一部です。それに合わせて、**言葉の重み（TF-IDF）と余弦類似度**で測っています。

| 重みを付けるもの | 重み |
|---|---|
| 分類（寺院・滝・城…） | 3 |
| 名前の終わりの字（〜寺・〜滝・〜城） | 1.5 |
| ジャンル（history・onsen…） | 1.5 |
| 名前の2文字ずつ | 1 |
| エリア | 0.6 |
| 説明の2文字ずつ | 0.4 |

文で探すとき（「紅葉の寺」）は、名前の終わりの漢字と分類の対応（「寺」→ 寺院、「滝」→ 滝。収録から数えたもの）を使って、1字からも分類を読みます。

比べたもの:

| しかた | 良いところ | 見送った理由 |
|---|---|---|
| **TF-IDF（採用）** | 外の部品なし。全国でも作るのに1〜2秒、探すのは一瞬。結果の理由を説明できる | 言い換え（「古刹」と「寺」）は拾えない |
| 埋め込み（Gemini・手元の LLM） | 言い換えに強い | 名前1語では差が出にくい。Gemini は使わないと決めている（Gemma だけ）。手元の LLM で5万件ぶん作るのは時間がかかる |
| FAISS などのベクトル検索の部品 | 数百万件でも速い | ネイティブの部品が要る。数万件では総当たりで足りる |

`--method=` は今は `tfidf` だけです。ほかを指すと、理由を書いて終了コード 2 で止まります。

## 評価

```bash
node tools/similar_eval.mjs
```

評価用のデータ（`tests/fixtures/similar-eval.json`）は、名前で探す12件と、文で探す3件です。それぞれ、上位5件のうち期待した分類に入るものの割合（precision@5）を測ります。

* いまの値: **0.987**（全国の索引）
* `tests/kbtools.test.js` は 0.9 を下回ると落ちます。重みを変えたら走らせてください

この指標は「同じ種類のものが出るか」だけを見ています。「行って楽しいか」「近いか」は見ていません。

## 出典とライセンス

* 切り出しにも索引にも、**元の出典の項目をそのまま残します**。`sources` は `kb/index.json` の一覧そのもので、`spotsBySrc` は出典ごとの件数です
* 外から取り込んだデータは、それぞれの提供元の条件に従います。とくに国土数値情報の観光資源（`src=kokudo`）・文化施設は**非商用で、再配布してよいかを確かめていません**。切り出したファイルを人に配る前に [data-licenses.md](./data-licenses.md) を読んでください

## まだやらないこと

* 切り出しを Web 版や API サーバーから読むこと（いまは CLI と `packages/core/kbtools.mjs` から）
* 季節・営業時間・距離を混ぜた並べ替え
* 意味の埋め込みを足した検索（収録に説明が増えたら考えます）
